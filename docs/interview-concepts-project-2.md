# Interview Concepts: Project 2 (Ignition Design Challenge)

**Do not use a “I completed the Design Challenge” story until that project’s checklist is done.** Until then, Project 1 is the only Ignition work you can claim.

## Why Project 2 exists

**Speak this:**  
After the pipeline portfolio was packaged, I used Inductive Automation’s free Design Challenge as extra Designer practice in a separate project. It is a coffee-roaster training spec, including machine control. It is not the energy SCADA application.

| Prompt | Answer |
|---|---|
| What is it? | Official training tasks: Gateway connections, UDT instances, Perspective overview/station/popup, security, alarms, optional Vision and reports. |
| Why do this after Project 1? | Project 1 is the interview product. The challenge is reps on Designer patterns (parameters, popups, notification pipelines) without mixing control into the pipeline HMI. |
| How did I use it? | *(Fill after `RioOso` is done.)* New project, not an extension of `PipelineOps`. |
| How can it fail? | Blending the two stories in an interview, or putting bidirectional pump control into the pipeline lab because the challenge required control. |

**If they ask which one is the portfolio:**  
`PipelineOps` / scada-operations-lab. The Design Challenge is practice.
